# Zotero-Cat v0.3.0

[English](https://github.com/Zotero-Cat/Zotero-Cat/blob/main/doc/release-notes/0.3.0.md) | [中文](https://github.com/Zotero-Cat/Zotero-Cat/blob/main/doc/release-notes/0.3.0.zh-CN.md)

Zotero-Cat is a Zotero item-pane AI assistant for reading, summarizing,
reviewing, and discussing research items with user-selected model providers.

## Download

Download `zotero-cat-v0.3.0.xpi` from the assets below and install it from
Zotero's Add-ons Manager.

Quick start:

1. Download `zotero-cat-v0.3.0.xpi`.
2. Open Zotero.
3. Go to `Tools -> Plugins`.
4. Install the XPI file.
5. Configure an OpenAI-compatible provider in Zotero-Cat settings.

## Compatibility

- Supported: Zotero 9.x
- Not yet declared: Zotero 10 beta

Zotero 10 compatibility will be declared only after the current Zotero beta line
passes the manual UI checklist.

## Highlights

This release focuses on provider/tool reliability and PDF-tool hardening.

- Native `tool_calls` turns now persist matching `role: "tool"` messages during
  the live session, preventing strict providers from rejecting the next request
  because of orphan tool-call history.
- Function Calling handling is now more standardized: provider quirks such as
  `reasoning_content` echo and native-tool unsupported fallbacks are tracked per
  endpoint, request message shaping lives in one module, and a single-turn
  runner performs known-quirk recovery before returning control to the Zotero
  UI/tool loop.
- Tool definitions now follow a lightweight MCP/OpenAI-compatible schema
  contract, so registered tools can export function specs consistently while
  Zotero-Cat still owns execution and human confirmation.
- Tool output and user-visible prose stay on separate runtime paths, with one
  inline activity row for long-running search, PDF read, annotation preparation,
  and annotation application work.
- PDF highlight/underline matching handles more realistic model quotes,
  including ellipsis-truncated text, long quotes with a non-verbatim tail,
  line-break dehyphenation, Unicode hyphen variants, and `cannot` / `can not`
  differences.
- Web search no longer defaults to only five results, and tool inputs can ask
  for `maxResults`, `count`, or `limit`.
- Manual context injection controls were removed from the chat controls when
  PDF tools are enabled, keeping the PDF flow tool-first instead of prompt
  pre-injection first.
- The agent UI/runtime refactor reduced `section.ts` to about 935 lines and
  moved tool-chain, UI rendering, model metadata, and provider helper logic into
  smaller modules.

## Upgrade Notes

Upgrade from `v0.2.0` by installing the new XPI. Existing settings and local
conversation history are preserved.

PDF tools remain experimental and off by default.

## Privacy

Zotero-Cat stores settings and custom context locally in Zotero preferences,
conversation history in a local JSON file, and API keys in Firefox Login
Manager. Content is sent only to the provider and optional search service
configured by the user.

See:

- [Privacy](https://github.com/Zotero-Cat/Zotero-Cat/blob/main/doc/PRIVACY.md)
- [隐私说明](https://github.com/Zotero-Cat/Zotero-Cat/blob/main/doc/PRIVACY.zh-CN.md)

## Known Limitations

- PDF tools are experimental and off by default.
- Highlight and underline text must be a continuous verbatim span from one PDF
  page; cross-page highlights need separate proposals per page.
- Scanned, encrypted, or OCR-poor PDFs may not provide reliable extractable
  text.
- Web search uses search snippets only; it does not crawl full webpages.
- Token budgeting is approximate.
- Model context length and reasoning-effort options depend on metadata returned
  by the provider.
- Zotero 10 beta support is not enabled yet.
